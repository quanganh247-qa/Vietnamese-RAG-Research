# Headless Colab and dataset EDA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for inline RED → GREEN verification.

**Goal:** Run a development RAG smoke test or a dataset EDA notebook on Colab without opening its notebook UI.

**Architecture:** Git Bash invokes the official CLI natively; provisioning and job execution are separate. Colab installs from a locked `uv` project, uses the existing Python RAG modules, and returns artifacts to the caller.

**Tech Stack:** Google Colab CLI 0.8.0, `uv`, Python 3.12, CUDA llama.cpp, Jupyter.

**Spec:** Approved conversation design: no WSL, no Colab website, allocate G4 → A100 → L4 → T4, and set up and run the model in Colab.

## Global Constraints

- Keep the existing run artifacts, frozen evaluation dataset and Transformers behavior unchanged. The new path is a separate dev pilot.
- Run paid GPU work only with Colab account access; do not put credentials in the repository.
- Notebook prose and research logs in Vietnamese; use test data only for aggregate EDA, never tuning examples.

## Review Focus

- Quota and entitlement failures fall through; authentication, network and model failures do not.
- Do not leave a session running on script failures; report cleanup errors with its name.
- Git Bash may translate Unix absolute paths when invoking Windows binaries. Transfer a relative archive name to Colab and convert the local path explicitly.
- Both official Q4_K_M shards are required. No silent CPU inference or silent model substitution.
- Similar wording is not a semantic or legal label and must not change benchmark splits.
